## Dates

Each commit is dated at noon (America/Chicago) on the day the change took effect. The other dates, enacted and published, are trailers.

When a law gives no date of its own, the default rule applies: No dated history is published: each act is the oldest version available, dated by the source's own currency statement. https://ndlegis.gov/general-information/north-dakota-century-code

## How the history is built

`tools/build.py` turns the corpus into this history in one pass: one commit per law, on the day it took effect. The same corpus always gives the same commit hashes. `tools/check_repo.py` reads every version back from git and compares it with the corpus. `tools/on.py` shows the law as it stood on any date. The corpus format is described in `tools/SCHEMA.md`.

## Decisions made by hand

- Each act is a single "oldest version available": the Legislative Council publishes only the current text of each chapter, with no dated history.
- Century Code acts are dated 2026-02-03, the date of the site's own note that all changes approved in the 2026 special session are reflected. The Constitution pages state no currency date, so its acts are dated 2026-10-29, the day before retrieval (2026-10-30): commits are dated noon local time, and a commit dated the retrieval day would lie in the future of the build.
- One act per chapter of the Century Code and one per Constitution article; one unit per section, keyed by the section number the Code prints. Section numbers are checked against the chapter's section list on the Century Code index page.
- Paragraphs are rebuilt from the PDF text layer: a line that ends in a space is wrapped onto the next one, and a numbering marker alone on a line, such as 1. or a., is put in front of the paragraph that follows. Page numbers ("Page No. 5") are dropped.
